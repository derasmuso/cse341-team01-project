## Implementation Reflection

5. Why did you decide to split your Feature Set into multiple GitHub issues or use a single issue?

Answer: I kept the page and API authorization work in one issue because both entry points expose the same booking records and must enforce the same administrator-only policy. Reviewing and testing them together makes it less likely that one route will remain publicly accessible.

6. What is one thing you know after completing the assignment that you did not know beforehand?

Answer: I learned that hiding an admin page in the interface is not sufficient security. The server must independently protect both the page route and the API that returns sensitive booking data, with different responses for signed-out users and users without the admin role.

7. What did you do to make your pull requests clear and ready for teammate review?

Answer: I linked the pull request to its implementation-spec issue, summarized the route protections, documented the 401 and 403 API responses, and listed the authorization tests and verification commands. I also ran the test suite and ESLint before requesting review.
