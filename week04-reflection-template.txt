## Implementation Reflection

5. Why did you decide to split your Feature Set into multiple GitHub issues or use a single issue?

Answer: I kept the feature set together in a single issue because the schema, model, route, controller, and UI work are interdependent and share the same data contracts. The booking flow depends on both the data model and the API behavior, so implementing and reviewing it as one end-to-end feature makes the work easier to test and easier for teammates to understand.

6. What is one thing you know after completing the assignment that you did not know beforehand?

Answer: I learned that Mongoose and the MongoDB connection setup must be coordinated carefully in tests. The app must connect to the same isolated in-memory database for model-backed tests so seeded data is available without affecting the real project data.

7. What did you do to make your pull requests clear and ready for teammate review?

Answer: I made the issue and pull request descriptions clear by including the implementation scope, the relevant links, a summary of the changes, and a list of the verified testing steps. I also ran the project test suite and lint checks before submitting the pull request so reviewers could evaluate the feature with confidence.
