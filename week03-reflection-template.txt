5. Why did you decide to split your Feature Set into multiple GitHub issues or use a single issue?

Answer: I would keep each feature set together as an end-to-end issue rather than divide its schema, model, API, and frontend work among separate issues. Those layers share data contracts, so implementing and reviewing them together makes the complete behavior easier to test. Separate issues for different feature sets would still keep each review focused.

6. What is one thing you know after completing the assignment that you did not know beforehand?

Answer: I learned that Mongoose uses its own connection even when the application also uses the MongoDB driver. The test setup must connect Mongoose to the same isolated in-memory database so model-backed API tests use the seeded test data without touching the team database.
